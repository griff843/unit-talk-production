# Sprint Proof Bundle — Evidence Rules

## Authority

Required artifacts derive from `docs/CLAUDE_OS_GOVERNANCE_CONTRACT.md` Sections
3–5. This file translates those rules into operational decisions.

---

## §Tier Classification

### How to determine the verification tier

**T1 — docs** Sprint changed ONLY documentation, governance files, or `out/`
artifacts. No application code, no schema, no tests modified.

Examples: `SPRINT-DOCS-CLEANUP-*`, `SPRINT-SYSTEM-TRUTH-AUDIT-*`

**T2 — build_fix / ui** Sprint fixed TypeScript errors, build configuration,
lint rules, or UI-only components with no business logic changes.

Examples: `SPRINT-TEST-INFRA-RECOVERY-*` (TypeScript fix portion only)

**T3 — runtime / schema** Sprint changed agent logic, lifecycle adapters,
database migrations, environment flags, or any code that runs at runtime.

Examples: `SPRINT-SINGLE-WRITER-COMPLETION-*`, `SPRINT-PROMOTION-ACTIVATION-*`,
any migration sprint, any agent behaviour change

**T4 — e2e_lifecycle** Sprint changed `unified_picks` write paths, Discord
posting pipeline, settlement logic, or any end-to-end flow involving the
lifecycle state machine.

Examples: Lifecycle adapter changes, settlement overhauls, posting pipeline
fixes

### Tier Assignment Table

| Sprint name pattern                             | Default Tier |
| ----------------------------------------------- | ------------ |
| `TRUTH-AUDIT`, `DOCS-*`, `CLAUDE-OS-*`          | T1           |
| `TEST-INFRA-*`, `BUILD-*`, `LINT-*`             | T2           |
| `SINGLE-WRITER-*`, `PROMOTION-*`, `MIGRATION-*` | T3           |
| Any sprint touching `unified_picks` directly    | T4           |
| `OBSERVABILITY-*`, `CONSENSUS-*`, `SCORING-*`   | T3           |
| Any sprint with migration files (`.sql`)        | T3           |

When in doubt, go **one tier higher**. The cost of extra evidence is low. The
cost of missing required evidence is a failed sprint.

## §Required vs Optional Evidence

### Required by ALL sprints (T1–T4)

| Artifact                    | Source               | Notes                                                     |
| --------------------------- | -------------------- | --------------------------------------------------------- |
| `proof_git_status.txt`      | `git status`         | Must be captured before any commit                        |
| `proof_typecheck.txt`       | `npm run type-check` | OR `proof_typecheck_scoped.txt` with documented exception |
| `SPRINT_CLOSEOUT_REPORT.md` | Manual (template)    | Must be fully populated, not template-skeleton            |
| `diffs/changes.diff`        | `git diff`           | Empty diff is only valid for T1 docs sprints              |

### Generated by Claude OS (do NOT create manually)

| Artifact                         | Generator      | Notes                        |
| -------------------------------- | -------------- | ---------------------------- |
| `proof_fetch_main.txt`           | `sprint:close` | Remote fetch output          |
| `proof_rebase_or_merge_main.txt` | `sprint:close` | Merge/push to main           |
| `proof_tag_exists.txt`           | `sprint:close` | Tag creation proof           |
| `proof_git_status_clean.txt`     | `sprint:close` | Clean state after merge      |
| `proof_proof_inventory.txt`      | `sprint:close` | MUST NOT be created manually |

Creating `proof_proof_inventory.txt` manually = sprint FAILED per governance
contract Section 3.

### Required by Tier (cumulative)

**T2 additionally requires:** | Artifact | Command | |----------|---------| |
`proof_build.txt` | `pnpm --filter api run build` |

**T3 additionally requires:** | Artifact | Command | |----------|---------| |
`proof_tests.txt` | `npm run test` | | `proof_runtime_*.txt` | See §Runtime
Proof Requirements |

**T4 additionally requires:** | Artifact | Command | |----------|---------| |
`proof_gate.txt` | `cd apps/api && npm run lifecycle:single-writer -- --strict`
| | `proof_e2e.txt` | `npm run test:e2e` (or documented exception) |

### Optional (recommended, not blocking)

| Artifact                     | When to include                                      |
| ---------------------------- | ---------------------------------------------------- |
| `notes/plan.md`              | Always, if sprint plan was created                   |
| `proof_session_baseline.txt` | When `pnpm session:baseline` was run at sprint start |
| `proof_lint.txt`             | For T2+ sprints where lint was relevant              |
| `notes/audit_summary.md`     | For T1 audit/truth sprints                           |
| `proof_migration_*.txt`      | For schema migrations — show migration output        |
| `proof_runtime_health.txt`   | For runtime sprints with running services            |

## §Runtime Proof Requirements

Runtime proof is **REQUIRED** (not optional) when the sprint:

1. **Enables a feature flag** — e.g., `PROMOTION_POLICY_V2=true`
   - Required: evidence the flag was tested in a running environment
   - Acceptable: agent health endpoint response, canary channel message, or log
     output

2. **Changes agent behavior** — e.g., GradingAgent promotion criteria
   - Required: at least one test or log showing the new code path executed
   - Acceptable: test output, `proof_tests.txt` showing the relevant test file

3. **Modifies database schema** — migration applied
   - Required: migration execution output
   - Acceptable: `supabase migration list` output or DB tool output

4. **Activates Temporal workflows** — `ENABLE_TEMPORAL_SCHEDULES=true`
   - Required: worker health endpoint or schedule listing
   - Acceptable: `curl http://localhost:3000/health/temporal` output

5. **Discord posting pipeline** — any posting-related change
   - Required: canary post evidence OR message from webhook
   - Acceptable: log line showing Discord API call, or screenshot

**What is NOT acceptable as runtime proof:**

- "I tested it locally" (no captured output)
- TypeScript compilation success alone
- Test files that test the wrong code path

## §Halt Conditions

Stop the proof bundle workflow and do NOT hand off to Claude OS if:

| Condition                                                                          | Resolution                               |
| ---------------------------------------------------------------------------------- | ---------------------------------------- |
| `proof_typecheck.txt` contains `error TS` AND sprint caused the error              | Fix TypeScript errors                    |
| `proof_typecheck.txt` contains `error TS` AND it's pre-existing BUT not documented | Document in closeout as scoped exception |
| `proof_tests.txt` shows test failures                                              | Fix failing tests                        |
| `proof_gate.txt` shows violations                                                  | Fix single-writer violations             |
| `SPRINT_CLOSEOUT_REPORT.md` is incomplete or has template placeholder text         | Fill all required sections               |
| `diffs/changes.diff` is empty for a non-docs sprint                                | Confirm correct branch is checked out    |
| Runtime proof required but not captured                                            | Capture runtime evidence                 |
| `claude_os_envelope.json` is missing or invalid                                    | Write/fix the envelope file              |

**One-liner halt check:**

```bash
grep -l "error TS" "$PROOF_DIR/proof_typecheck.txt" && echo "HALT: TypeScript errors"
grep -c "FAILED\|✗" "$PROOF_DIR/proof_tests.txt" | grep -v "^0$" && echo "HALT: Test failures"
grep "GATE FAILED\|violations found: [1-9]" "$PROOF_DIR/proof_gate.txt" && echo "HALT: Gate violation"
```

## §Scoped Verification Exceptions

When repo-wide checks fail due to pre-existing issues (not this sprint):

### Approved scoped lanes

| Lane flag           | Scope             | When to use                                      |
| ------------------- | ----------------- | ------------------------------------------------ |
| `--lane api`        | `apps/api/` only  | When test suite broken but API changes are sound |
| `--lane ops-submit` | ops-submit module | For ops-submit specific changes                  |

### How to document a scoped exception

In `SPRINT_CLOSEOUT_REPORT.md`, add this section:

```markdown
### Scoped Verification Exception

**Reason**: Repo-wide [type-check | tests] fails due to pre-existing
DRIFT-[C1|C2] which is not caused by this sprint.

**Sprint-relevant scope**: `apps/api/src/<path>` **Scoped check**:
`proof_typecheck_scoped.txt` — PASSED **Pre-existing failures**: Documented in
DRIFT_REPORT.md

This sprint did not introduce or worsen the pre-existing failure.
```

## §Docs Sprint (T1) Reduced Requirements

For docs-only sprints, the following are NOT required:

- `proof_build.txt`
- `proof_tests.txt`
- `proof_gate.txt`
- `proof_e2e.txt`
- Runtime proof of any kind

Still REQUIRED even for docs sprints:

- `proof_git_status.txt`
- `proof_typecheck.txt` (to confirm no .ts files were broken by accident)
- `SPRINT_CLOSEOUT_REPORT.md` (populated)

Empty diff (`diffs/changes.diff`) is acceptable ONLY for docs sprints where all
changes are to `.md` files only.
