## 1. Sprint Lifecycle Phases

Every sprint follows these phases in order:

```
Plan → Implement → Verify → Proof → Closeout Validation → Commit → Tag → Merge
```

| Phase               | Description                                                 | Gate                               |
| ------------------- | ----------------------------------------------------------- | ---------------------------------- |
| Plan                | Document objective, acceptance criteria, required artifacts | SPRINT_PLAN.md created             |
| Implement           | Write code, create/modify files                             | Code complete                      |
| Verify              | Run verification lane (full or scoped)                      | Exit code 0                        |
| Proof               | Capture all required proof artifacts                        | All files present                  |
| Closeout Validation | Run `sprint:close` command                                  | Exit code 0                        |
| Commit              | Create commit with sprint ID in message                     | Commit created                     |
| Tag                 | Create tag matching sprint ID exactly                       | Tag created                        |
| Merge               | Push to origin/main                                         | Branch up to date with origin/main |

---

## 2. Definition of "Complete"

A sprint is COMPLETE if and only if ALL of the following are true:

1. **Merged to main**: Local main and origin/main are synchronized.
2. **Canonical tag exists**: Tag name equals sprint ID exactly (no suffix).
3. **Proof bundle exists**: `out/sprints/<SPRINT-ID>/<DATE>/proofs/` contains
   all required artifacts.
4. **Proof inventory generated**: `proof_proof_inventory.txt` exists and was
   generated by tooling.

If ANY condition is false, sprint status is NOT COMPLETE.

---

## 3. Mandatory Proof Inventory Rule

### Required File

Every sprint proof bundle MUST contain:

```
proofs/proof_proof_inventory.txt
```

### Generation

This file MUST be generated by the `sprint:close` command, not manually created.
It contains a recursive listing of the sprint folder and validates required
artifacts.

### Validation

The `sprint:close` command validates this file exists and contains expected
artifacts. If validation fails, the command exits non-zero and the sprint cannot
close.

## 4. Required Proof Artifacts (Baseline)

Every sprint MUST have these artifacts in the proof bundle:

| Artifact                         | Purpose                                  | Required    |
| -------------------------------- | ---------------------------------------- | ----------- |
| `proof_git_status.txt`           | Initial git state                        | YES         |
| `proof_typecheck*.txt`           | TypeScript verification (full or scoped) | YES         |
| `proof_verify_lane.txt`          | Verification lane output (if scoped)     | CONDITIONAL |
| `proof_fetch_main.txt`           | Fetch from origin                        | YES         |
| `proof_rebase_or_merge_main.txt` | Merge/push output                        | YES         |
| `proof_tag_exists.txt`           | Tag creation proof                       | YES         |
| `proof_git_status_clean.txt`     | Clean state after merge                  | YES         |
| `proof_proof_inventory.txt`      | Auto-generated inventory                 | YES         |

Additional sprint-specific proofs may be required based on sprint scope.

## 5. Verification Lane Policy

### Full Verification

When repo-wide typecheck and tests pass:

```bash
npm run type-check
npm run test
```

### Scoped Verification

When repo-wide verification fails due to pre-existing issues unrelated to sprint
scope:

1. A scoped verification lane MAY be used.
2. The scoped lane MUST be documented in the sprint plan.
3. The scoped lane MUST be fail-closed (exit non-zero on failure).
4. The scoped lane MUST NOT weaken enforcement for sprint-relevant code.

Approved scoped lanes:

- `--ops-submit`: For ops-submit module changes
- `--api`: For API-only changes

### Invocation

```bash
# Full verification
npm run sprint:close -- <SPRINT-ID> --lane full

# Scoped verification
npm run sprint:close -- <SPRINT-ID> --lane ops-submit
```

---

## 6. Ban on --no-verify

The `--no-verify` flag is PROHIBITED for all sprint commits.

- Pre-commit hooks MUST run.
- If hooks fail, fix the issue. Do not bypass.
- Commits using `--no-verify` invalidate the sprint.

Violation consequence: Sprint marked FAILED. Must re-execute with proper
verification.

## 7. Tag Convention

### Format

Tag name MUST equal sprint ID exactly:

```
SPRINT-<NAME>-<ID>
```

### Examples

| Sprint ID              | Correct Tag            | Incorrect Tag                  |
| ---------------------- | ---------------------- | ------------------------------ |
| SPRINT-GOVERNANCE-079  | SPRINT-GOVERNANCE-079  | SPRINT-GOVERNANCE-079-COMPLETE |
| SPRINT-OPS-SUBMIT-071C | SPRINT-OPS-SUBMIT-071C | SPRINT-OPS-SUBMIT-071C-DONE    |

### Enforcement

Tag MUST match the `out/sprints/` folder name exactly.

## 8. Closeout Validator Requirements

The `sprint:close` command MUST:

1. Accept sprint ID as argument.
2. Auto-detect latest date folder OR accept explicit date.
3. Run verification lane (full or scoped).
4. Generate `proof_proof_inventory.txt` with recursive listing.
5. Validate all required artifacts exist.
6. Print compliance table:

```
============================================================
SPRINT CLOSEOUT VALIDATION
============================================================
Sprint: SPRINT-EXAMPLE-001
Date: 2026-02-20

COMPLIANCE TABLE:
Artifact                          | Required | Found | Path
----------------------------------|----------|-------|----------------------------------
proof_git_status.txt              | YES      | ✅    | proofs/proof_git_status.txt
proof_typecheck*.txt              | YES      | ✅    | proofs/proof_typecheck.txt
proof_fetch_main.txt              | YES      | ✅    | proofs/proof_fetch_main.txt
proof_rebase_or_merge_main.txt    | YES      | ✅    | proofs/proof_rebase_or_merge.txt
proof_tag_exists.txt              | YES      | ✅    | proofs/proof_tag_exists.txt
proof_git_status_clean.txt        | YES      | ✅    | proofs/proof_git_status_clean.txt
proof_proof_inventory.txt         | YES      | ✅    | proofs/proof_proof_inventory.txt

STATUS: ✅ ALL REQUIRED ARTIFACTS PRESENT
============================================================
```

7. Exit non-zero if ANY required artifact is missing.

```

```

## 10. Consequences of Violation

| Violation                       | Consequence           |
| ------------------------------- | --------------------- |
| Missing proof artifacts         | Sprint status: FAILED |
| Using --no-verify               | Sprint status: FAILED |
| Tag name mismatch               | Sprint status: FAILED |
| Manual proof_inventory creation | Sprint status: FAILED |
| Skipping closeout validation    | Sprint status: FAILED |

Failed sprints MUST be re-executed with proper compliance.

## 11. The ONE Command

To close any sprint:

```bash
npm run sprint:close -- <SPRINT-ID>
```

This is the only authorized way to finalize a sprint.
